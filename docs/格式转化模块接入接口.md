# 格式转化模块接入接口

主入口保持“上传数据 + 目标模型”，后台依次自动识别、自动融合、自动转化。不再通过页面让用户选处理算法。旧科学模块仍保留在后台。

## 队友需要实现的唯一接口

在队友模块的 Python 包中注册入口，例如 pyproject.toml：

```toml
[project.entry-points."ecodata.model_converters"]
swat_plus = "teammate_converter:convert"
```

安装该包后平台自动发现，无须增加页面按钮。每个模型只能注册一个转换器。

```python
def convert(manifest_path, output_dir):
    # manifest_path: pathlib.Path，UTF-8 JSON
    # output_dir: pathlib.Path，转换文件只写入此目录
    # 读取清单中 products 的 NetCDF，结合团队自己的工程/格式适配逻辑。
    # 缺少必要工程或字段时返回失败，不能生成占位原生输入。
    return {
        "status": "PASS",
        "files": ["相对输出目录的真实文件名"],
        "validation": {"这里填写实际执行的校验记录": "及其结果"},
    }
```

清单协议为 `ecodata.converter.v1`，包含 model_id、products（相对于清单目录的文件路径和 SHA256）、preparation（识别记录、逐变量处理结果、实际搜索/质量记录）。字段级准备不表示已齐备整个模型所需数据或工程。

转换器应校验：模型版本、必需变量和工程依赖、单位、时间粒度/区间、目标网格、文件引用关系及原生格式。`PASS` 必须表示这些适用于本转换场景的检查已完成。原生模型是否实际运行，另记录实际运行证据，不等同于文件转换。

平台在返回前校验输出文件存在、非空且路径没有越出输出目录。转换失败会保留数据准备包，不把它标为模型原生输入。转换器缺席时状态为 `AWAITING_CONVERTER`，第三步显示“待接入”。

## 本次自动入口的边界

自动识别复用现有文件识别、模型字段别名匹配和单位换算；同变量的多源处理调用公共随机变异数值入口。完整单源保留原观测。未匹配模型字段、分类变量、坐标/单位缺失、多用途歧义会给出原因并停止，不猜测元信息。

这是已有算法入口的简化界面，不是新增任意数据自动理解能力。尚未为未知表结构、任意协变量关系、模型工程目标网格和所有原生格式新增适配。信息必须足够才能自动继续；这些科学限制不能靠隐藏选项消除。


## WRFDA 3DVAR 原生后端（2026-11-05）

现有界面不新增控件；WRF输入中检测到实际wrfvar配置时进入WRFDA适配，普通数据继续使用原随机变异流程。本次只支持非辐射观测的3DVAR；未确认的辐射配置、4DVAR、冲突输入均不能静默改成普通3DVAR。原数据与原配置保留，工作配置中的旧数据兼容开关、背景土地类别数绑定及用户明确确认的常规观测范围差异进入bindings.json。

Linux后端复用WRF官方v4.7.1，commit f52c197ed39d12e087d02c50f412d90d418f6186；tools/bootstrap_wrfda_linux.sh在专用Linux环境编译GNU serial WRFDA及NetCDF依赖，不修改科学源码。需要ecodata账户及/opt/ecodata目录；本机通过独立QEMU/WHPX Ubuntu24.04环境提供，未启用Windows系统功能，不需要重启宿主机。不能直接把Linux executable当Windows程序运行。

Windows部署辅助：安装项目的wrfda-setup附加依赖；在自行选择的独立runtime目录准备经过发布校验的QEMU程序（含share固件）及downloads/ubuntu-noble.img，再运行 tools/setup_wrfda_vm.py --runtime-dir <目录>。Ubuntu原像使用20261103 noble minimal，SHA256 bc9237bfdfa42b5f9a4404b6c6cab595d3e57599c6498f6664ad00e6192f9595；新镜像不可冒用该哈希。QEMU来源https://qemu.weilnetz.de/，发布清单可核对ScoopInstaller/Main的qemu.json。setup仅生成隔离overlay、私有密钥、NoCloud启动介质和启动参数，不改系统服务或PATH。用qemu_args.json的参数隐藏启动qemu-system-x86_64；Linux内自动安装构建依赖并编译，日志为/opt/ecodata/bootstrap.log、compile.log，成功后生成runtime.json。密钥、seed.iso和VM磁盘不得提交Git。

构建后运行 tools/register_wrfda_backend.py <runtime目录>/connection.json；核实SSH主机密钥、源码commit与程序SHA后注册到当前用户LOCALAPPDATA/EcoDataEngine/wrfda_backend.json，并安装可信任务执行器。配置仅供运维，不能由上传数据覆盖，不增加页面选项。平台下一次同化会自动连接本机后端；已配置的VM未启动时按安装参数隐藏启动。后台默认只接受loopback连接，科学资料不会自动发送外部服务器。运行环境和大型原数据不放GitHub源码仓库。

用户上传原工程ZIP/TAR或文件夹，选择WRF即可。需唯一明确的3DVAR配置、相符时刻/网格的真实wrfinput、对应观测窗口的OBSPROC .3DVAR资料及be.dat。原始LITTLE_R未经过OBSPROC时不能冒充已处理观测。第二套北极案例经用户确认，仅常规观测复验：在原包旁附schema=ecodata.wrfda-task.v1、mode=3dvar、observation_scope=conventional、confirmed=true的task.json。该声明是用户任务范围，不能用于隐藏修改其他科学参数；没有明确声明则保留辐射需求并拒绝不支持的任务。

成功产物为COMPONENT_EXPORTED，下载中有原生wrfvar_output、使用的namelist、输入指纹、原生执行日志、代价函数和分析场检查。不能只凭退出码0成功：必须有原生完成标记、真实可读分析场、正确时刻网格、有限数值/基本物理检查、状态增量，以及观测代价为正且总目标下降。这个结果不等于侧边界已更新、WRF预报已运行或独立精度已提高。
