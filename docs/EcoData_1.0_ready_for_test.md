## 2. 明天按此顺序操作

### 案例 1：真实水质 CSV → NetCDF → CSV

输入：`01_真实水质表格回转\水质真实数据.csv`。

1. 首页“上传一个或多个数据文件”，选择这一份 CSV。
2. 在“自动识别结果”和“数据预览”查看采样时间、断面名称、水质类别及各水质指标。
3. “输出目标”保持“自定义输出”；“输出格式”选 **NetCDF**。
4. 系统默认勾选化学需氧量、氨氮、总磷、总氮。它们应为连续数值，单位应为 **mg/L**，无需手填。
5. 不勾选时间处理，不做融合。没有经纬度，所以不应要求 CRS 或空间分辨率。
6. 点“执行数据转换”，展开“自动质量检查”，再点“下载转换结果”和“下载处理与模型匹配报告”。
7. 清除 CSV，上传刚下载的 `.nc`；输出改选 **CSV**；保持表格结构、无时间处理，执行并下载。

正常结果：67,728 条记录、13 个原始字段保留；四个水质指标是数值类型，不再出现 `b'0.11'` 字符串；年份、月份保持整数；断面等文字字段保留。NetCDF 内保留单位与来源属性。回转 CSV 表头使用清理后的变量名，单位不嵌在表头，应同时保存 JSON 报告。

本次已逐字段验证数值、文字和缺失位置；数值回转容差为相对 `1e-10`、绝对 `1e-12`。这里是格式保真验证，不是水质预测精度。

失败含义：若要求空间转换，是当前任务设置选错；若数值变字符串、字段丢失或回读值改变，是转换缺陷，应视为失败，不应继续展示“成功”。不允许补造这份真实数据的经纬度。

### 案例 2：GeoTIFF → NetCDF → GeoTIFF

输入：`02_遥感栅格回转\遥感样本.tif`。

1. 只上传这一份 TIFF，输出选 **NetCDF**。
2. 数据结构选择“保持当前结构，仅转换文件容器”；变量为 **value**。
3. CRS 自动读取为 **EPSG:32618**，源像元约 **0.300 km**。单位原文件未知，只测试格式时可以留空；若需要时空处理，应明确填 `unknown`，不能填写污染浓度单位。
4. 目标空间分辨率保持 **0**，表示不处理；不进行时间处理。
5. 执行，检查质量报告并下载 `.nc`。
6. 清除 TIFF，上传刚下载的 NetCDF；输出选 **GeoTIFF**，保持结构、分辨率 0；执行并下载。

正常结果：128×128、1 波段，CRS 为 EPSG:32618；有效像元 **16,329**；回转像元值、缺失位置和 transform 保留。投影坐标在 NetCDF 中叫 **x/y**，不是错误标为 lat/lon。存储可以由 uint8 变为 float64，原来的 NoData=0 对应输出 NaN，不算物理数值损失。

失败含义：“全部 NaN”“没有有效像元”表示所选层/范围没有可输出数据；“CRS 丢失”“transform 改变”表示定位保真失败。不能靠更改 CRS 字符串来重投影。

用 QGIS 打开 TIFF；图片查看器无法识别科学栅格不等于文件损坏。QGIS 安装包此前已在 `D:\codex\QGIS安装包`，本次没有另行安装软件。

### 案例 3：Shapefile → GeoTIFF

输入：`03_湖泊矢量栅格化\湖泊Shapefile.zip`。上传整个 ZIP，不必解压；其中包括 `.shp/.shx/.dbf/.prj`。

1. 上传该 ZIP，输出选 **GeoTIFF**。
2. 系统自动显示 geometry 类型、CRS、extent 和可用数值属性，无需填写范围。
3. 栅格化字段选 **scalerank**；它是制图等级，不是水质数据。
4. “目标栅格分辨率（度/像元）”填 **0.5**。这里坐标系是经纬度，单位为度，**不是 0.5 km**。
5. “栅格化策略”选 **所有接触像元**；“重叠要素策略”选“后出现的要素优先”，内部标识 **last**。
6. 执行、展开自动质量检查、下载 TIFF 和报告。

正常结果：自动生成覆盖全部湖泊的 470×168 栅格；有效像元 **587**，未覆盖区域是 NoData。原始矢量有 24 个湖泊面要素。

如果要先查看矢量转换，可以先输出 GeoJSON，再上传 GeoJSON 用相同设置栅格化。对于只有文字属性的数据，系统自动生成 **value=1 覆盖掩膜**，这只表示覆盖，不是新增观测浓度。

失败含义：没有可用数值属性不是必须失败，可用掩膜；极细分辨率超过本地上限，应增大像元大小；重叠错误需要明确选择策略，不会默默覆盖。

### 案例 4：多源检查 → 对齐 → 加权融合

输入：`04_多源标准化融合_合成诊断` 根目录内两份 `.nc`，**不要同时上传其中“已验证结果”或补充案例的文件**。

这是明确标注的合成诊断，不是真实 COD 观测。A 为 EPSG:32618、1 km、2 小时、1 mg/L；B 为 EPSG:4326、不同网格、4 小时、0.003 g/L。两源声明 physical_variable=COD、瞬时值及 uncertainty；其重叠范围和单位都有已知定义。

1. 同时上传 **A_投影网格_2小时_mgL.nc** 和 **B_经纬网格_4小时_gL.nc**。
2. “主数据文件”选 **A**，输出 **NetCDF**；处理变量只选 **value**。
3. 勾选“进行时间分辨率转换”，目标时间分辨率填 **1h**，时间语义为 **瞬时值**。
4. “目标空间分辨率 km”填 **0.5**，保留自动算法。需要手动选择时展开“高级设置：算法选择”，选双线性或最近邻。
5. 勾选“对多个兼容网格进行数据融合”，“融合方式”选 **多源反方差加权融合**。
6. 查看兼容性表、不能融合的原因（本案例应没有）、“自动处理流程”。系统将换算 B 的单位，插值共同时间点，投影到 A 的 CRS 和目标网格，再融合。
7. 执行，查看报告中的“标准化与融合”和“自动质量检查”，下载结果与报告。

正常结果：**5 个小时点×6×6 网格**，时间为 2021-02-01 00:00～04:00；全部 value 约 **2 mg/L**。两源换算后 sigma 都为 1 mg/L，因此权重相同；uncertainty 约 0.7071 mg/L。这是已知常量诊断，不应宣称真实独立验证精度。

失败含义：缺少 physical_variable/uncertainty/CRS、单位不能换算、时间不重叠、没有有效空间重叠时不得猜测融合。算法只在共同时间范围内插，不向两端外推；不确定度插值暂不估计重采样协方差或跨源相关性。

补充测试：进入 `04_多源标准化融合_合成诊断\补充_背景场与站点残差融合`，同时上传 **背景场.nc** 和 **监测站_合成诊断.csv**，主数据选背景场，输出 NetCDF；不设时间/空间转换；勾选融合，方式改为 **背景场 + 监测站残差融合**。正常 value 为 **3 mg/L**，background_value 为 1、residual_correction 为 2；INVALID 站点不能参与修正。当前只支持同一明确时间点、EPSG:4326、二维背景网格，其他情况应先单独对齐。

### 案例 5：数据 → WASP 的一类输入 → 标准化输出

复用案例 1 的真实水质 CSV，避免重复保存另一份原始数据。

1. 上传 `01_真实水质表格回转\水质真实数据.csv`。
2. “输出目标”选 **环境模型**；“目标模型”选 **WASP**。
3. “我要把当前数据转换成哪一种模型输入”选 **water_quality_state**。
4. 系统列出当前数值指标，默认选 COD/氨氮/总磷/总氮对应原字段。确认单位 mg/L，输出 NetCDF。
5. 执行并下载标准化文件和匹配报告。
6. 需要检查 WASP 的整个输入是否齐全，再单独展开 **模型完整性检查**；不要把其他模型输入缺失当成本任务必须失败。

正常结果：能输出水质状态预处理数据，匹配范围 `selected_input`；保留 67,728 条记录的原始字段、单位和来源。

**重要边界：WASP 这一输入类型的逐变量原生字段 Schema 尚未由真实模型案例验证；本次 `field_schema_verified=false`、`can_generate_native_model_input=false`。断面尚未绑定 WASP segment_geometry，不能声称输出文件可以直接运行 WASP。** 完整性检查仍会列出 segment_geometry、flow 等依赖。这与“把当前水质数据先标准化”是两件事。

## 4. 本次实际修改

复用统一 RequirementStore 和已有 23 个模型索引，不重新建模型库；复用单输入类型匹配、自定义模型保存、结构转换、时间处理、最近邻/双线性/保守重网格、QP 和 P2 融合算法，不新增研究算法。

主要补齐：

1. 多源单位、瞬时值时间、CRS 和网格自动对齐，再调用原反方差融合；共同范围内插、不外推。
2. 暴露已有 P2 背景场＋站点残差融合，明确支持边界与质控规则。
3. 修复缺测来源仍参与分母而使融合结果偏低的问题。
4. 修复处理后投影坐标导出时仍写作 lat/lon 的路径；标准科学数据输出使用现有统一导出器。
5. 输出回读检查覆盖记录、字段、数值、缺失、时间/坐标、科学数据数值类型、单位、CRS 和元数据键；GeoTIFF 检查尺寸、波段、transform、有效像元和 NoData。
6. 输出有效比例、NaN 比例、min/max、分辨率、范围等。对于同范围/同时间、明确 cell_mean/flux 的规则场，比较面积积分；保守重网格误差超过 1e-6 判为失败。其他语义不冒充守恒性。
7. 数值全无效、空文件、字段丢失、CRS 丢失等不得显示成功；CSV 等容器不完整携带环境属性，报告必须随结果保存。
8. 多文件部分失败报告及 results.zip。自动识别增加缺失统计、网格范围、重复站点时间去重后的时间步长；不再将主文件分辨率猜测给其他文件。
   加权融合遇到 qc_flag 时只接受明确的 VALID/INVALID/MISSING 定义、仅 VALID 参与；原标记统计记入流程，输出另外标记融合有效性，不把派生标记冒充原始质控结果。
9. 算法选择及 QP 高级参数默认折叠；已有单位、CRS 自动读取；动态时间处理读取已有时间语义，未声明时要求确认。

## 5. 当前架构与支持范围

前端仍是一个数据转换任务，后台分别负责：

`recognition.py` 识别 → `task.py` 编排现有 Pipeline → `io/structures.py` 结构/格式 → `temporal/`、`spatial/`、`fusion/` 处理 → `models/` 匹配 → `evaluation/output_quality.py` 实际输出检查 → `interface/downloads.py` 打包。

支持容器：CSV、TSV、Excel、JSON、Parquet、NetCDF、HDF5-NetCDF、GeoTIFF、GeoJSON、Shapefile ZIP。真实结构路径包括表格↔科学数组、规则网格↔像元中心点、矢量栅格化、分类栅格多边形化；并非仅修改后缀。

限制：原生任意 HDF5 需要明确 dataset 与坐标映射；旋转栅格、曲线网格、Shapefile Z/M、任意站点自动填满规则网格不宣称普遍支持。GeoTIFF 输出需选择一个二维变量/时间层。当前本地空间转换有 200 万单元保护。经纬度像元不能未经定义就显示固定 km 分辨率。只有可换算的单位支持自动换算，未知单位不能参与物理融合。保守/QP 不自动用于跨 CRS 融合对齐，应先单独转换。

模型状态：统一库共 **23 个**，其中 **22 个需求索引、1 个标准化预处理（WASP）、0 个已验证原生适配**。自定义模型可编辑保存。模型索引较粗，不能以“已收录”代替原生字段、依赖与真实运行验证。
