# Robit单源降水重建：链路与小规模效果交付

## 结论

本阶段链路已通：真实文件输入→三画像联合评分→公共ALNS变异→候选真实数值执行→隔离测试→既有SWAT+62天气写出器→回读数值和日期。未运行SWAT+模型、未改队友流域工程，不评价径流精度，不宣称多源融合或空间精细化。

**评分确实生效，但没有证明优于强固定方案或随机搜索。** 最强开发固定方案和仅评分推荐的测试RMSE均为7.747872mm/day；评分＋ALNS为8.457340mm/day，比固定方案高9.16%，与无评分ALNS、随机对照相同。负结果原样保留，未在看过测试结果后调权重或更换算法池。

## 数据与隔离

- 直接使用队友交付包的`ClimateRobit`，原始逐日降水、最高/最低温、辐射、湿度、风速均为1990—2013年8766天，有限且完整。温度最高不低于最低，其他变量按原文件单位保留。
- 处理对象仅降水；其他气象数值在导出后逐列回读，与原资料一致。
- 1990—1995：拟合12个月的历史平均降水及降水标准差。1996—2001：开发期执行全部40图，冻结最强固定算法/图。
- 2002—2007：搜索验证；2008—2013：路径冻结后测试。各阶段各有3个两年案例，分别为随机单日、连续3天、连续14天缺口，约遮挡10%的原本已知值。保留首尾观测，只研究内部缺口；未验证端点外推。
- 人为遮挡前的原始数值是本轮重建参考，不等于已独立核实的地面真值。没有使用`observedFlow.csv`，没有把1990年短程模型结果与1993—1997年月流量对比。
- 3个时段/缺口案例配对比较，3个搜索种子只是优化器重复，不当作9个独立流域，不做泛化显著性宣称。

## 复用及必要适配

公共入口仍为`ecodata.algorithms.platform_search.submit_search`。复用`Composition`的候选计数、完整筛选、实际执行、缓存、质量门、验证反馈、选图与产品持久化，复用`composition_optimizers`中的ALNS＋AlphaUCB＋HillClimbing；没有重写优化器或调用研究脚本作为平台后端。

旧时间服务限定小时PM2.5，旧并行探测要求两套空间场。此次只补逐日站点恢复适配：

1. 复用原有pandas/SciPy线性、最近邻、前填内核；把纯数值函数从原图模块移到`temporal_kernels`并保持原导入接口，避免单独调用日算法时强依赖GOLEM导入顺序。
2. 新增历史月均值填补适配，只读取显式早于输入期的拟合状态，不在验证/测试重拟合。
3. 公共组合入口支持单站时间任务及完整、有依据的显式链备选；仍逐项校验，按规范结构去重，不能随机截断候选空间。
4. 在已有模型画像入口增加已存在的`swat_plus`画像，使用weather/precipitation字段，避免拿SWAT2012画像冒充SWAT+。
5. 单点坐标仅承载真实站点位置，数据形状time×1×1不是空间栅格插值证据。

算法规格均为真实可执行适配；没有引入新预测网络、训练另一套排序器或冒称科学插值算法创新。

## 候选图与真实协作

冻结40种结构：4个单方法，及4×3个不同的短/长方法分配×3个长度阈值（1、3、7天），共4+36=40。短支节点仅填满足长度的原有缺口，后续方法节点处理剩余缺口，原有有效观测不改；真实执行后的非有限输出会失败，不会只计算成功子集误差。

这是本轮有限语法，不代表整个算法库全部可能组合。纯长度缺口案例会使多个图数值等价；每个案例实际只有少量不同数值产品，不能将40图吹大为40种不同科学行为。`independent_audit.json`保留每次执行的不同数值产品数。

为明确证明两段方法都参与，另在训练/开发期1996—1997做混合1/3/14天缺口定向验收：公共入口执行“短缺口线性→剩余缺口历史月均值”，两个节点分别实际填补11天和42天，53个缺测全部恢复，有效原值保持不变，SWAT+降水文件回读通过。**这是工程验收，既不是新独立测试，也没有替换正式测试的负结果。**

## 三画像评分怎样参与

复用既有并行评分汇总；为单站日数据增加可见值遮挡探测。每次完整筛选前，把输入中另一些可见日值隐藏，按真实缺口长度分布生成探测缺口，对全部40图实际执行；原验证遮挡真值不进入节点或评分探测。

- 数据画像：实际缺失比例、缺口长度分布、可见序列与训练期尺度。数据路得分为`1/(1+探测RMSE/训练标准差)`。
- 算法响应：记录整条候选链真实处理前后的状态及探测误差，不以能力覆盖率代替数值执行，也不假定两个算法收益能直接相加。
- 模型画像：SWAT+逐日降水的有限、非负、保留观测，以及显式声明的输入总量偏差代理。模型路调用公共`Composition.score`与注册属性的状态风险归一化；`expected_error`在本范围明确指探测平均偏差绝对值/训练标准差，**不是SWAT输出误差**。没有起点真值的维度继续保留区间。
- 数据路、模型路各0.5为实验前冻结的工程优先级，未声称是学得的SWAT敏感性；协同奖励权重为0，避免靠相对自身改善得分。没有填造模型响应。
- 40个候选产生3或4个不同评分区间，已确认不是全部同分；但分数不同不等于能提高测试效果。

评分影响初始化和画像引导修复；后续接受变异与选图以明确授权的验证RMSE反馈为准。最终测试只执行冻结路径，不反馈。

## 对照结果

测试误差只在原本已知且被遮挡的位置计算，3个案例共232个遮挡日；搜索种子重复不增加独立评价天数。

| 方案 | 测试RMSE（mm/day） | 测试MAE（mm/day） |
|---|---:|---:|
| 固定线性 | 10.087601 | 4.222586 |
| 固定最近邻 | 11.484134 | 4.359914 |
| 固定前填 | 12.812776 | 4.904741 |
| 固定历史月均值 | **7.747872** | **3.764027** |
| 开发期冻结的最强固定图 | **7.747872** | **3.764027** |
| 仅三画像评分 | **7.747872** | **3.764027** |
| 三画像评分＋ALNS | 8.457340 | 4.032181 |
| 无评分初始化＋ALNS | 8.457340 | 4.032181 |
| 随机8图 | 8.457340 | 4.032181 |
| 随机40图，覆盖冻结池 | 8.457340 | 4.032181 |

本轮开发期最强固定图实际上退化为单独历史月均值，并未得到优于单算法的组合。评分＋变异没有胜过随机；只评分追平强固定，不能宣称已经学会优于固定算法的组合选择。

差异主要发生在随机单日案例：验证期更偏好前填，测试期该方案RMSE7.992247，而固定月均值5.228515。短缺口及长缺口案例最终误差与固定月均值相同。说明验证选择存在泛化问题；不能通过增加搜索预算保证独立测试更好，也不能把有限候选池验证最优叫作未知真实效果的全局最优。

## 搜索成本与完整证据

每次常规搜索8张真实验证图、相同候选池与种子，评分组另有40次可见遮挡探测；仅评分为1张验证图加40探测。随机成本对照上限40，已覆盖全部候选池，**不是严格相同墙钟成本**。缓存命中与原始kernel调用在轨迹中分别标记。

| 方案 | 平均验证图数 | 额外探测图数 | 平均服务秒数 |
|---|---:|---:|---:|
| 评分＋ALNS | 8 | 40 | 0.907 |
| 无评分ALNS | 8 | 0 | 0.578 |
| 随机8图 | 8 | 0 | 0.587 |
| 随机40图 | 40 | 0 | 2.123 |

这批小任务上评分＋变异比随机8图多成本却没有提高效果，不宣称净效率优势。绝对时间只代表本机本次输入，未将文件I/O或缓存成本隐藏。

独立回读核验了开发/验证699张真实图、480次探测的记录，最终测试21个不同图产品对应54条方案/种子比较记录，原始有效观测保持、标签隔离、训练状态、原生天气输出数值与日期均通过。混合缺口验收另计，不混入统计效果。

另对冻结的480次可见遮挡探测做了独立重放，误差及各路分数与原搜索记录一致，并保存预测值供重算；这些额外480次只属于审计成本，不计为搜索优势。41项不同定向/兼容测试全部通过。

## SWAT+输出与交付边界

使用现有`SWATPlusAdapter.save_package`，没有改写SWAT+科学模型或队友工程。5类天气均回读验证：恢复降水与产品一致，其他变量与原资料一致；按输出精度容差0.00051检查，逐日日期完全一致。

当前本地写出器还会生成不完整的候选`file.cio`；它不代表完整工程。为避免误覆盖队友设置，另提供`weather_handoff`目录，仅含5类站点天气文件与对应索引，**不带file.cio、time.sim、HRU、河道或WGN**。队友应保留自身工程、WGN和站点分配，只接入这些天气数据。未用官方模型运行这些输出，不将“格式写出并回读通过”描述为“SWAT+模型效果已验证”。

`delivery/`另提供拼接好的2008—2013完整2192天气象：原始完整数据、固定历史月均值、仅三画像评分、三画像＋变异seed11、随机seed11五套，每套只替换降水，全部回读通过，便于交队友继续接入。不得将此完整期与只有1993—1997年的径流观测直接对比。

接入过程中遇到的请求字段错误、测试导入顺序错误、旧测试仍假定七个画像及对候选file.cio的错误预期均修复或纠正；早期失败日志、测试报告、第一次导出副本保留。修复没有改变验证冻结路径或测试数值目标，没有为了出优势更换规则。
