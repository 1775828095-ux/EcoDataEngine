# WRF 多站同时段气温补缺

在现有桌面平台选 WRF，打开只含一对已登记命名的输入或其 ZIP。支持
`WRF_background_surface_*.nc` 和 `surface_observations_*UTC.csv`，原工程 ZIP
可以包含其他成员。入口验证实际字段、单位、投影和时间，按同一时刻的历史补缺运行。
结果包括五种对照、开发与冻结后的留站评分，以及可评分缺测站的 CSV。平台使用
已接通的 DeepSeek 连接，只发送训练配对样本和开发评分，最终留出实测只在本地使用。

可在资料 ZIP 内附一个 `wrf_station_gap_policy.json`，或把该 JSON 放在上传目录中。
该 JSON 需要以下三个字段：

- `min_mae_gain_k` 为融合相对开发阶段选定的最佳单源所需的最小总体 MAE 改善，正数，单位 K。
- `max_block_mae_increase_k` 为任何有参考的空间块允许的最大 MAE 增量，非负数，单位 K。
- `basis` 为本次阈值所依据的业务要求。阈值须在最终留出使用前确定。

未声明时，平台会请 DeepSeek 查询适用的公开规范并核对引文。查不到可验证的局部
限度时，总体 MAE 仍必须改善。各空间块的实际退化继续报告，局部限度显示为未设。
本地固定方案提供对照。只有 DeepSeek 明确提名且在开发空间块达标的融合方案进入选优。
开发不达标时，平台带着本轮误差、偏差方向和分块退化继续提名，最多四轮。
最终留站只验收冻结后的融合候选及对照。达到本批门槛时交付融合补缺结果。
页面展示算法、参数和同批单源对照。适用范围为该时刻和验证空间支持，跨日期效果需新数据验证。
