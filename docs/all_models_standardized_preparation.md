# 24 个模型标准化数据准备能力

## 当前完成范围

全部 24 个内置模型现在都有字段级最小准备契约，并统一使用现有流程：

上传 → 识别 → 角色匹配 → 字段/单位检查 → 标准化 → 输出检查。

系统状态统一为 `standardized_preprocessing`，含义是平台可以整理用户已经提供的
物理数据；不表示已经生成完整原生工程，更不表示官方模型运行成功。

| 类别 | 模型 |
|---|---|
| 大气与气象 | AERMOD、AERSCREEN、CALPUFF/CALMET、CMAQ、CAMx、HYSPLIT、WRF、WRF-Chem、SMOKE |
| 水文水动力 | SWAT、SWAT+、PRMS、VIC、HEC-HMS、HEC-RAS、SWMM |
| 水质地下水 | WASP、EFDC、CE-QUAL-W2、EPANET、MODFLOW 6、MT3D-USGS、SEAWAT |
| 陆面生态 | CLM/CTSM |

## 新增的共享字段契约

新增契约覆盖排放源、受体、气象、地形、网格、节点、管线、降雨、温度、土壤、
土地利用、HRU、流量、水质状态、浓度、输运参数、时空分配、工程映射及配置参数。
相同物理角色复用同一模板，避免为每个模型复制转换逻辑。

已有 CMAQ、WRF、CAMx、SWAT+、CALPUFF、WASP 和 MODFLOW 6 的更详细场景保持
原样；共享契约只补原来没有字段定义的17个模型。

## 守门规则

- 只有上传数据中真实存在的字段才能匹配。
- 单位不兼容、全缺失、数据类型错误时拒绝转换。
- 只上传部分角色时，可以下载该角色的标准化结果，但整个模型完整性保持 FAIL。
- 控制参数、拓扑、边界、动力学参数和上游模型输出不能凭空生成。
- 所有标准化输出继续经过回读和 Validator 检查。
- `native_model_input_verified` 对所有未执行官方程序的模型保持 false。

## 验证

- 检查全部24个模型均具有非空字段契约。
- 对新增17个模型分别执行至少一条真实标准化输出路径。
- 对新增17个模型分别构造完整、明确的角色集合，验证 ProcessingPlanner 可以生成
  无缺失的处理计划。
- 完整模型计划通过不等于官方模型输入通过；测试明确检查
  `native_model_input=false`。
