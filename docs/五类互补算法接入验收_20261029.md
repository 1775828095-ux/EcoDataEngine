# 五类互补算法接入验收（2026-10-29）

五类方法已注册到平台默认算法库，并验收公共图生成、随机变异及真实数值执行。本轮只补算法及连接机制，未开展正式效果实验。

## 实际接入

|公共节点|真实后端|条件及作用|
|---|---|---|
|`temporal.whittaker`|官方VAM Whittaker 2.0.6 `ws2d`编译内核|时间平滑及补缺；至少四个等间距时刻，每像元至少两个有效观测。非等间距先接时间对齐。可能平滑真实峰值。|
|`reconstruction.dineof`|sinkr 0.8.0固定提交的原始R `dineof`函数|时空低秩补缺；复用现有R 4.5.2，调用base R SVD。每时刻及像元需足够有效观测，不能凭空恢复整期完全无观测的数据。|
|`fusion.guided_filter`|OpenCV contrib 5.0.0.93 `ximgproc.guidedFilter`|两个父节点分别是引导源和目标源；当前要求同变量、同物理含义、单位及坐标严格一致。不把任意DEM纹理当作目标变量真细节。|
|`spatial.arosics_coreg`|AROSICS 1.13.2 `COREG.calculate_spatial_shifts`及SciPy亚像元重采样|逐帧估计全局图像平移，并在原网格上取样；不是局部非刚性形变。边缘缺失保留，交给后续节点处理。|
|`fusion.starfm`|starfm4py固定提交原始`predict`内核|使用可见同日细/粗源锚点与目标时刻粗源反射率。当前支持0—1地表反射率；两源须对齐，传感器不确定度须明确提供，不给NDVI或降水冒填参数。|

sinkr提交：`dd3f9e119ee6a41e4e44f4be2051914c223f2bb6`；starfm4py提交：`b1a917f68f88fe9f274d99d29a8e0eaac24892b3`。DINEOF使用成熟sinkr实现，未冒称执行了另一套Fortran发行版。

Whittaker目标是`sum(w*(y-z)^2) + lambda*sum((D2*z)^2)`；缺失w=0，观测w=1。验收用独立矩阵求解对照官方输出。lambda是可搜索的算法参数，不是另造画像评分权重。

DINEOF只在可见输入中设置内部遮挡以选择EOF模式，记录随机种子和所选模式，保护原始有效值。外部验证/测试标签不传入算法。STARFM保留上游零值筛选约定；窗口没有有效贡献者时拒绝，不暗中改用另一种算法。

## 先后、主次和逐源处理

复用已有DAG、父节点契约、参数提议、科学状态去重和质量门；没有新增整图模板池或另一套搜索器。

- 已执行`Whittaker→STARFM`和`STARFM→Whittaker`两种顺序，两者输出确实不同；并非节点换个排列名称。
- 缺失数据先补缺，再进入要求完整栅格的去噪/引导节点；配准造成边缘缺失后，再接已有栅格补缺。
- 引导滤波区分guide/target，配准区分reference/moving，STARFM区分fine/coarse；角色写在节点参数中，可以由平台探索，不由上传顺序暗定。
- 不同源可以分别补缺、平滑和对齐，再汇合；不强迫每个源经过相同处理。
- STARFM按目标时刻选择最近的完整可见同日锚点，历史重建允许两侧可见锚点，不宣称未来预测。
- 配准需显式`parameters.allow_image_coregistration=true`；公共请求的`constraints.forbid_spatial_shift=true`会否决它，不能任意移动模型物理场。

修复了与配准后补边直接相关的问题：原栅格补缺把投影坐标一律当作经纬度，现按声明CRS区分处理。AROSICS内核及后续补缺已检查投影坐标；公共全图验收采用平台已有的规范`time,lat,lon`地理坐标。当前公共栅格变异/部署链仍有这一坐标契约，未宣称所有x/y投影文件都能未经转换直接搜索。

未知精度收益、守恒和范围保持继续标UNKNOWN；没有为新增方法编造画像效果或人工加分。满足契约的算法真实可调用，不等于所有变量与格式都适用。

## 环境与来源

主环境新增OpenCV contrib，保留原NumPy 2.5.3；dask 2026.8.0、zarr 3.4.1复用现有安装。主依赖记录在`requirements-advanced-complements.txt`及项目`advanced-complements`可选依赖。

AROSICS/GDAL使用`external/geo-runtime/env`独立Python 3.11，版本为AROSICS 1.13.2、GDAL 3.13.1、NumPy 2.4.6。Whittaker官方Windows轮子依赖NumPy1 ABI，从`external/geo-runtime/whittaker-packages`专用NumPy 1.26.4路径在另一进程加载；不降级平台或AROSICS环境。ABI失败日志保留，错误副本已移除。STARFM参数也在独立进程中设置，避免不同任务串扰。

当前环境已经安装并真实执行。地理环境精确包URL在`geo_runtime_explicit.txt`；Whittaker官方轮子、源码、哈希、固定提交及许可证保留在证据目录。

- [VAM Whittaker官方发行](https://pypi.org/project/vam.whittaker/2.0.6/)与[MODAPE说明](https://github.com/WFP-VAM/modape)：实际用前者可核验的发行包，没有移植完整MODAPE流程。
- [sinkr DINEOF原函数](https://github.com/marchtaylor/sinkr/blob/dd3f9e119ee6a41e4e44f4be2051914c223f2bb6/R/dineof.R)。
- [OpenCV引导滤波](https://docs.opencv.org/4.x/da/d17/group__ximgproc__filters.html)、[AROSICS](https://github.com/GFZ/arosics)、[starfm4py](https://github.com/nmileva/starfm4py)。执行版本以封存环境及哈希为准。

## 验收结果及证据

1. 五类均真实执行：Whittaker核对独立数学解；DINEOF检查遮挡恢复、观测保护及重复性；引导滤波检查父源扰动与单位一致性；AROSICS核对已知平移方向及恢复；STARFM检查粗源时间变化的数值响应。
2. 现有GraphMutation在完整公共注册表上自动生成节点和连接。测试人员从生成编辑中选择以覆盖五类，最终包含五类和补边的图由公共无标签入口完成7次注册调用。它证明可达及可执行，不代表生产优化器被要求使用五类，也不证明搜索最优。
3. 回归74项通过，补验公共空间移动否决及最终生成图检查；合计75项不重复检查通过。初始失败日志保留。
4. 已有2015真实开发NDVI经`DINEOF→时间插值→Whittaker`与另一源处理后引导融合，输出46×16×16，7次注册调用；独立重放逐值一致。未读2018留出真值。AROSICS/STARFM另经受控影像和自动生成全图验收，没有把NDVI改名反射率。
5. 正式精度对照未跑，`scientific_advantage=NOT_EVALUATED`。验收公共文件/API及共用链路，页面点击流程未单独验收。旧正式实验目录未改写。

证据目录：`output/complementary_five_20261029/`。关键文件：`algorithm_profiles.json`、测试XML/日志、`real_development_acceptance.json`、`independent_audit.json`；`pytest_final_boundary/test_public_registry_automatic0/`保存自动生成配置、输入、图和部署台账。
