# EcoData Engine 1.0 操作说明

## 打开软件

1. 打开 `D:\codex\EcoDataEngine` 文件夹。
2. 双击 `start_ecodata_1_0.bat`，或直接双击桌面的 `EcoData Engine 1.0`。
3. 等待浏览器打开 `http://localhost:8501`。运行期间不要关闭后台服务窗口。

若尚未安装运行环境，请在项目目录执行：

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[test]"
```

## 模式 A：模型适配检查

1. 上传数据并查看自动识别结果。
2. 选择“模式 A：模型适配”和目标模型。
3. 软件读取该模型的需求配置，列出已匹配和缺少的数据组。
4. 缺少必要物理变量时不会自动生成；适配状态不是“已验证”时，只提供需求检查，不输出声称可直接运行的模型文件。

模型名、required input、变量名、文件名、维度名和 package 名保持官方英文，不作生硬翻译；中文只用于操作说明。

## 模式 B：自定义转换

1. 默认进入“数据处理”。选择“一键加载 PM2.5 示例”或上传 CSV、TSV、Excel、JSON、GeoJSON、Parquet、NetCDF 或 NetCDF-compatible HDF5；支持一次选择多个文件。
2. 查看识别结果和数据预览。单位、时间语义或坐标无法可靠识别时，必须人工填写或确认。
3. 选择“模式 B：自定义转换”，设置变量、数据语义、输出格式、目标时间和空间分辨率。
4. 连续量可用时间插值、重网格和融合；分类量只自动使用最近邻；计数、文字和标识符没有明确物理规则时不会被数值插值。
5. 点击“开始自动处理”，查看处理前后数据、图像、算法决策、转换历史和运行时间。
6. 下载 CSV、TSV、JSON、Excel、NetCDF、NetCDF-compatible HDF5、Parquet 或 GeoJSON 结果，以及 JSON 处理报告。没有独立参考真值时，软件不会显示 MAE、RMSE 等精度指标。

GeoTIFF、Shapefile 和 GRIB 已登记到格式能力表，但当前没有安装并验证相应读写器，因此界面不会把它们伪装成可用格式。

标准站点 CSV 应包含：`station_id,time,latitude,longitude,variable,value,unit,qc_flag`。当前仅对连续瞬时站点数据执行时间插值。网格 NetCDF 当前要求规则的 `lat`、`lon` 坐标，并用 `grid_resolution_km` 明确标注源分辨率。

## 多文件与算法实验

### 在普通转换页面使用 QP

选择“模式 B：自定义转换”，在“空间算法”中可选择普通约束 QP、自适应平滑 QP、自适应平滑＋可信峰值约束 QP 或原始峰值感知 QP。

使用内置示例时会提供配套训练站选项；上传自己的数据时，同时上传粗网格和训练站表格，明确选中训练站文件并确认时间语义。训练站须包含 split=train 和 qc_flag=VALID，变量、单位和时间必须与网格相符。

展开“优化条件”可设置最大迭代次数、求解精度、初始插值方法、拟合/平滑权重及峰值条件。结果中会显示实际迭代次数和约束误差。调整参数后需要重新点击“开始自动处理”。更多说明见 `按老师建议逐项改进.md`。

### 其他说明

- 多个同变量、同坐标网格都含 `uncertainty` 时，可在明确勾选后执行反方差多源融合；软件不会擅自把其他文件当作融合源或参考真值。
- 左侧进入“算法对比实验”，可比较普通 QP、P3.2 自适应方法和原始峰值感知 QP。
- 左侧进入“模型需求库”，可浏览 24 个模型的版本、必需数据、原生格式、输出及官方资料；传统 SWAT 与 SWAT+ 是独立条目。
- 无法处理的转换会直接显示原因，例如缺少单位、非规则网格、缺少时间边界或空间分辨率不是整数倍关系。
# 新增：格式与数据结构转换

左侧选择“格式与数据结构转换”。上传一个文件，确认变量、坐标、单位和 CRS，选择结构转换方式与输出格式，点击“执行格式转换”，下载结果及 JSON 报告。

可直接使用 `D:\codex\EcoData Engine 1.0\格式转换示例` 下的 6 个示例；逐项操作方法见同级 `格式转换操作说明.txt`。支持范围和不支持的情况见 `格式结构转换说明.md`。该页面不替代原有多源融合和算法实验页面。
