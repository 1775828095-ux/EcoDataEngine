# EcoData Engine 1.0：P0 技术设计

> 状态：设计基线（P0）  
> 日期：2026-09-29  
> 范围：仅定义 1.0 的数据语义、接口、处理链路与实验方案；不代表已完成实现、真实数据验证或 CMAQ 兼容性验证。

## 1. 目标与验收边界

EcoData Engine 1.0 面向生态环境模拟数据的读取、语义校验、清洗、融合、时空尺度转换、模型适配、质量验证与导出。它统一的是内部数据表示、元数据和操作接口，而不是强制统一所有文件格式。

P0 完成的判据：

1. 数据字段及物理语义有明确的数据字典。
2. 表格、网格和矢量数据进入算法前有统一对象约定。
3. 算法输入、输出、质量记录和异常行为有统一接口。
4. 时间、空间、融合和模型适配之间的衔接规则明确。
5. 局部极值感知约束降尺度可作为空间算法接入，而非独立旁路。
6. P1 的最小可运行链路、测试与成功条件可直接实施。
7. 真实数据及目标模型中尚未知的信息被显式列出，不以假数据补齐。

本阶段不实现代码、界面、自研算法或 CMAQ 文件生成器。

## 2. 设计原则

- **语义先于数组**：任何重采样或融合前，必须知道变量含义、单位、时间支持区间和空间含义。
- **显式转换**：单位、坐标、时间语义和网格变化必须形成可审计记录。
- **算法不直接读写文件**：Reader 负责解码，Writer 负责编码，算法仅处理统一对象。
- **转换与验证分离**：算法不能自行宣布结果有效；独立 Validator 生成验证报告。
- **保守失败**：缺字段、单位不兼容、分类变量误用连续插值、禁止外推等情况应明确报错。
- **确定性**：相同输入、配置、依赖版本与随机种子产生相同结果。
- **最小实现**：1.0 只实现经过样例和测试支撑的算法组合，不提前建立通用自动规划系统。

## 3. 统一内部数据表示

### 3.1 顶层对象 `EcoDataBundle`

Pipeline 的唯一业务输入与输出为 `EcoDataBundle`。它是逻辑对象，不要求把所有内容塞进一个文件。

| 字段 | 类型 | 必需 | 含义 |
|---|---|---:|---|
| `dataset` | `xarray.Dataset` | 是 | 规范化后的多维连续、离散或网格变量 |
| `observations` | `pandas.DataFrame` 或空 | 否 | 尚未栅格化的站点长表观测 |
| `geometries` | `geopandas.GeoDataFrame` 或空 | 否 | 区域、边界、土地利用等矢量对象 |
| `metadata` | `DatasetMetadata` | 是 | 数据集级来源、CRS、约定和处理状态 |
| `history` | `list[TransformRecord]` | 是 | 按执行顺序追加的转换记录 |

对象只持有数据及说明，不负责选择算法。单一场景不需要的数据成员可为空。

### 3.2 `xarray.Dataset` 约定

标准维度名优先采用 `time`、`x`、`y`、`level`；经纬度坐标采用 `latitude`、`longitude`。曲线网格允许二维经纬度坐标。原始字段名保留在来源映射中，不要求源文件预先改名。

每个进入转换流程的业务变量至少具有以下属性：

| 属性 | 示例 | 规则 |
|---|---|---|
| `standard_name` | `mass_concentration_of_pm2p5_ambient_aerosol_in_air` | 有可靠 CF 名称时使用；否则为空并保留本地名称 |
| `long_name` | `PM2.5 mass concentration` | 必需，表述物理含义 |
| `units` | `ug m-3` | 必需；无量纲使用 `1` |
| `data_kind` | `continuous` / `categorical` | 必需，决定可选算法 |
| `temporal_semantics` | `instantaneous` / `mean` / `accumulation` | 有时间维时必需 |
| `spatial_semantics` | `point` / `cell_mean` / `cell_total` / `flux` | 有空间维时必需 |
| `valid_range` | `[0, null]` | 可选物理范围，不用于静默裁剪 |
| `source_variable` | `PM25` | 必需，支持回溯 |
| `uncertainty_variable` | `pm25_uncertainty` | 可选，引用同 Dataset 中的不确定性变量 |
| `ancillary_variables` | `pm25_qc` | 可选，引用质量标记 |

坐标必须携带单位；空间数据必须可解析 CRS。经纬度默认候选为 EPSG:4326，但只有源数据或配置明确时才能赋值，禁止仅凭数值范围猜定。

### 3.3 站点观测长表

最低字段如下：

| 字段 | 类型 | 必需 | 约束 |
|---|---|---:|---|
| `station_id` | string | 是 | 同一来源内稳定且非空 |
| `time` | datetime64 | 是 | 必须明确时区或明确标记为无时区的约定时间 |
| `latitude` | float | 是 | 合法纬度范围 |
| `longitude` | float | 是 | 合法经度范围 |
| `variable` | string | 是 | 映射到规范变量名 |
| `value` | numeric | 是 | 缺失值保持缺失，不隐式填补 |
| `unit` | string | 是 | 每条记录或每个变量唯一可解析单位 |
| `qc_flag` | string/int | 是 | 原始标记保留；含义由映射表解释 |
| `uncertainty` | numeric | 否 | 与 value 同单位，或另有明确表达 |
| `source_id` | string | 是 | 指向来源记录 |

同一 `station_id` 的坐标变化必须被检查；移动平台不能伪装成固定站点。

### 3.4 地理矢量数据

`GeoDataFrame` 必须具有非空 CRS、`geometry` 和稳定的 `region_id`。`elevation`、`land_use` 等仅在来源给出或有明确派生方法时保存。分类字段不得通过双线性或 Kriging 插值。

### 3.5 元数据与追踪记录

`DatasetMetadata` 至少包含：`dataset_id`、`source_uri`、`source_format`、`source_checksum`、`crs`、`calendar`、`conventions`、`created_at`、`software_versions`。

每个 `TransformRecord` 至少包含：

- `operation_id`、`method`、`parameters`；
- 输入变量与输出变量；
- 输入摘要校验值；
- 开始/结束时间、运行时长和峰值内存；
- 警告、质量标记、随机种子；
- 相关配置及软件版本。

该记录用于重现和审计，不取代完整日志。

## 4. 数据字典与物理语义

### 4.1 首批变量族

| 数据族 | 主键/维度 | 代表变量 | 必须确认的语义 |
|---|---|---|---|
| 空气质量站点 | station、time、variable | PM2.5、PM10、O3、NO2、SO2、CO | 瞬时或小时平均、单位、质控含义、检测限 |
| 气象网格/站点 | time、space、level | temperature、humidity、pressure、wind_u、wind_v | 高度/气压层、平均窗口、风分量坐标系 |
| 排放 | time、grid、species | emission_value | 质量或摩尔量、速率或累计量、面积基准、时间窗口 |
| 地理 | geometry、region | elevation、land_use | CRS、垂直基准、分类编码 |
| 模型输出 | time、x、y、level、variable | concentration 等 | 网格投影、层定义、时间戳含义、缺测编码 |

### 4.2 时间语义决定转换

| 时间语义 | 降采样 | 升采样 | 禁止的默认行为 |
|---|---|---|---|
| 瞬时连续值 | 采样或按配置聚合 | 线性/PCHIP，可选且不外推 | 把瞬时值当区间累计量 |
| 区间平均值 | 按区间重叠时长加权平均 | 仅在明确假设下分配/插值 | 忽略原区间边界直接线性插值 |
| 区间累计值 | 对完整覆盖区间求和 | 按规则分摊并保持总量 | 对累计值取平均 |
| 分类/状态 | 众数、末值或领域规则 | 前向保持或最近邻 | 数值线性插值 |

时间坐标应配套 `time_bounds` 表达区间。若源数据为平均或累计但缺少区间边界，进入需要区间运算的流程前必须报错或要求配置补充，不得猜测。

### 4.3 空间语义决定转换

| 空间语义 | 推荐方法 | 核心检查 |
|---|---|---|
| 点连续观测 | IDW、Kriging、最近邻 | 留出验证、距离/投影合理性 |
| 网格点连续场 | 双线性、最近邻 | 坐标单调性、边界与掩膜 |
| 单元平均量 | 保守重网格化或有依据的双线性 | 面积权重与重新聚合误差 |
| 单元总量 | 面积交叠分配 | 全域总量守恒 |
| 通量 | 面积与时间单位共同换算 | 积分量守恒、单位一致 |
| 分类变量 | 最近邻或面积多数类 | 类别集合不新增 |

经纬度上的距离计算不得直接当作平面米制距离；IDW、Kriging 和邻域算子应先使用适合区域的投影坐标或球面距离实现。

## 5. 统一算法接口

为避免过度抽象，P1/P2 只定义以下四类协议。

### 5.1 Reader / Writer

```python
class Reader(Protocol):
    def read(self, source: Path, config: ReadConfig) -> EcoDataBundle: ...

class Writer(Protocol):
    def write(self, data: EcoDataBundle, target: Path, config: WriteConfig) -> WriteResult: ...
```

Reader 只做格式解码、显式字段映射和元数据提取。Writer 不得在输出时重采样、填值、换单位或裁剪。

### 5.2 Transform

```python
class Transform(Protocol):
    name: str
    def validate_input(self, data: EcoDataBundle, config: TransformConfig) -> CheckReport: ...
    def apply(self, data: EcoDataBundle, config: TransformConfig) -> TransformResult: ...
```

`TransformResult` 包含 `data`、`record`、`warnings`。输入校验失败时不得返回看似正常的结果。输入默认按不可变对象看待，输出为新对象或清晰记录的副本。

时间重采样、空间重网格、插值、融合和优化均实现该协议。算法专用参数放入各自配置模型，不使用无结构字典穿透整个系统。

### 5.3 Validator

```python
class Validator(Protocol):
    def validate(self, before: EcoDataBundle | None,
                 after: EcoDataBundle,
                 config: ValidationConfig) -> ValidationReport: ...
```

`ValidationReport` 包含结构检查、单位检查、缺失值变化、坐标检查、守恒误差、约束违反、数值指标、运行性能和最终 `pass/fail`。阈值必须来自配置。

### 5.4 ModelAdapter

```python
class ModelAdapter(Protocol):
    def inspect(self, data: EcoDataBundle, profile: ModelProfile) -> CompatibilityReport: ...
    def adapt(self, data: EcoDataBundle, profile: ModelProfile) -> TransformResult: ...
```

Adapter 只执行配置允许且物理上可定义的重命名、维度整理、单位转换和格式准备。缺失的必要物理变量必须报错，不生成占位值冒充真实数据。

## 6. 算法注册、选择与衔接

### 6.1 Registry

Registry 以稳定方法名映射到实现及能力描述，例如 `temporal.linear`、`spatial.bilinear`、`spatial.conservative`、`fusion.residual_kriging`、`downscale.constrained`、`downscale.peak_aware`。能力描述至少声明：支持的数据类型、时间/空间语义、必需坐标、可否处理缺失值及是否可能外推。

Registry 不自动猜算法。Pipeline 根据显式策略和能力检查选择；若方法与变量语义冲突则拒绝执行。

### 6.2 Pipeline 顺序

```text
Reader
  -> Schema/metadata validation
  -> QC filtering (保留原始标记和掩膜)
  -> Unit normalization
  -> Coordinate normalization
  -> Temporal transform（如需要）
  -> Spatial transform / downscaling（如需要）
  -> Fusion（如需要）
  -> ModelAdapter
  -> Independent Validator
  -> Writer
```

并非每条链路都执行所有步骤。步骤由配置显式列出；Pipeline 负责传递对象、追加历史、统一失败状态和调用验证，不在内部实现算法。

关键衔接约束：

1. 单位不统一时不得融合或计算误差。
2. CRS 不确定时不得执行依赖距离或面积的空间算法。
3. 时间支持区间不一致时不得直接合并变量。
4. 背景场与观测必须是同一物理量、兼容单位和可比较时间窗口。
5. 质控剔除只改变有效掩膜，不覆盖原值；报告有效样本变化。
6. 空间变换产生的覆盖外区域默认保持缺失，不外推。
7. 任何降级方法必须由配置允许，并写入 `TransformRecord`，不得静默发生。

### 6.3 基础选择规则

| 条件 | 首选候选 | 排除项 |
|---|---|---|
| 连续瞬时量时间对齐 | 线性；峰值敏感时加入 PCHIP 对照 | 范围外默认外推 |
| 平滑网格连续场 | 双线性 | 分类变量 |
| 单元平均/总量且要求守恒 | 保守重网格化 | 未知网格边界 |
| 站点到网格连续量 | Kriging 或 IDW | 未投影距离、无留出验证 |
| 分类变量 | 最近邻/多数类 | 线性、PCHIP、Kriging |
| 同物理量多源估计 | 不确定性加权 | 不同变量或不兼容时间窗口 |
| 背景场 + 站点 | 残差插值 | 训练站与验证站混用 |

## 7. 数据融合定义

### 7.1 不确定性加权

对同一位置、时刻、物理量且误差假设成立的多个估计值，使用预先给定或可验证的不确定性权重。缺少不确定性时不能默认把数据源视为等精度；可在配置明确时使用等权基线，并在报告中标记假设。

输出除融合值外，还应包含来源贡献权重、有效来源数和可计算时的传播不确定性。

### 7.2 背景场残差融合

1. 将背景场映射到训练监测站位置。
2. 在相同单位和时间支持下计算观测减背景残差。
3. 仅用训练站对残差做 IDW/Kriging。
4. 将残差场加回背景场。
5. 使用独立留出站评价，不参与拟合。

若站点落在背景网格覆盖范围外、时间不重叠或质控失败，则不进入残差训练集。

## 8. 局部极值感知约束降尺度的接入

### 8.1 在空间模块中的位置

峰值感知方法注册为 `downscale.peak_aware`，输入和输出仍为 `EcoDataBundle`。它依赖一个已注册的基础空间方法产生 `x0`，不自行读取文件或重复实现双线性/保守重网格。

```text
粗网格 y + 目标网格
  -> 基础重网格器 -> 初值 x0
  -> 算子构造器生成 A、H、E
  -> 预先计算可信度与平滑权重 W0、Wz、WE
  -> 稀疏凸二次规划
  -> 约束与独立指标验证
  -> 高分辨率结果 x + 质量报告
```

### 8.2 输入契约

- `y`：带明确 `cell_mean`、`cell_total` 或其他已支持空间语义的粗网格变量；
- `target_grid`：坐标、单元边界、CRS 和掩膜完整；
- `x0`：基础方法在目标网格上的初值；
- `z`：可选且经质控的同变量监测值；
- `A`：由网格几何及变量空间语义构造的稀疏聚合算子；
- `H`：高分网格到监测点的稀疏映射算子；
- `E`：考虑边界、掩膜和距离的稀疏邻接差分算子；
- 权重与不确定性：在求解前确定并记录，不能根据待求结果追认峰值。

### 8.3 优化形式

基础目标保持为凸二次形式：

```text
min α||W0(x-x0)||² + β||Wz(Hx-z)||² + γ||WE Ex||²
```

约束按变量语义启用：`Ax = y`（严格守恒且数据相容时）、`x >= 0`（确实非负的物理量）。观测和粗尺度数据存在已知误差或冲突时，守恒或观测项可改为带不确定性权重的软约束，但模式必须由配置显式指定。

“峰值感知”仅通过外部观测/辅助信息预先降低可信峰值邻域的平滑权重或提高观测权重实现。不得加入无依据的峰值最大化项。

### 8.4 求解状态与降级

求解结果至少区分 `optimal`、`optimal_inaccurate`、`infeasible`、`unbounded` 和 `solver_error`。默认行为：非最优状态不写出正式结果；只有配置明确允许时，才可返回基础结果 `x0`，同时将状态标记为 `degraded` 并保留原因。

大网格仅使用 SciPy 稀疏矩阵和适用的 CVXPY/OSQP 表达。P3 实施前需先通过小网格算子正确性测试，随后再评估内存规模。

## 9. 模型配置与适配边界

`ModelProfile` 至少包含：

| 字段 | 作用 |
|---|---|
| `model_id`, `model_version` | 精确标识目标规范 |
| `required_variables` | 必需物理变量及可选变量 |
| `variable_mapping` | 内部名到模型名的显式映射 |
| `required_units` | 每个变量的目标单位 |
| `required_dimensions` | 维度名、顺序和长度约束 |
| `target_grid` | 投影、坐标、边界、层定义 |
| `time_requirements` | 日历、时区、频率、时间戳语义 |
| `output_format` | 编码格式、压缩、缺测值等 |
| `validation_rules` | 必须通过的结构及数值检查 |

`generic_cf` 可作为 P1/P2 的首个可验证 profile。CMAQ profile 只能在具体版本、文件类别及官方字段规范确认后实现；普通 CF-NetCDF 输出不得标注为“CMAQ 兼容”。

## 10. P1 第一条可运行链路

### 10.1 固定范围

采用自行生成但真值已知的小型空气质量数据，不使用未确认的真实字段：

```text
CSV 站点 PM2.5 小时观测
  -> CSV Reader
  -> 字段/单位/时间/QC 检查
  -> 转为规范站点长表
  -> 线性时间对齐到固定小时轴（不外推）
  -> 站点数据保存为 NetCDF 的 observation 维 Dataset
  -> NetCDF Writer
  -> 重新读取
  -> 独立自动验证
```

这一链路优先验证统一表示、时间语义、缺失值、读写往返和审计记录。它不宣称完成空间降尺度；P1 若时间与额度允许，再增加一个独立的规则网格双线性样例，但不作为首链路通过条件。

### 10.2 P1 成功标准

1. 合成 CSV 可被读取，必需字段缺失时明确失败。
2. 单位和变量映射来自配置，不从名称臆测。
3. 时间轴与预期完全一致，范围外不产生值。
4. 缺失值与质控掩膜没有被静默填充。
5. NetCDF 写回并重读后，数值、关键属性和时间坐标一致。
6. 每步产生顺序稳定的转换记录。
7. 自动测试覆盖正常链路及至少单位冲突、非法时间语义和禁止外推三类失败。
8. 示例可由单条命令执行，固定配置与依赖版本，并生成验证报告。

## 11. 实验计划

### 11.1 分阶段数据

- P1：小型确定性表格与网格，用于接口和往返正确性。
- P2：已知函数生成的平滑场、边界突变、多峰场、缺测和多噪声场。
- P3：将高分辨率真值聚合为粗网格，再由各算法恢复；训练观测与验证观测固定划分。
- P4：经许可获得的真实数据和目标模型样例；先结构验证，再做实际模型运行验证。

### 11.2 对照与消融

空间对照：最近邻、双线性、保守重网格、Kriging、普通约束优化、峰值感知约束优化。只在方法适用的变量语义上比较。

P3 消融至少包括：

1. `x0` 基础结果；
2. 初值项 + 平滑项；
3. 加入观测约束；
4. 加入预先确定的自适应平滑权重；
5. 严格守恒与软守恒（仅在误差设定合理时）。

所有实验固定数据划分、随机种子、配置和版本；不根据验证集调参。

### 11.3 指标

| 维度 | 指标 |
|---|---|
| 整体精度 | MAE、RMSE、偏差 |
| 峰值保护 | 峰值幅值误差、峰值位置距离、预定义极值区域 MAE |
| 一致性 | 重新聚合 MAE/最大误差、相对总量误差 |
| 物理约束 | 负值数量/幅度、约束最大违反量 |
| 缺失处理 | 输入输出有效样本数、意外填充值数量 |
| 效率 | 端到端运行时间、算法时间、峰值内存、规模曲线 |

峰值区域阈值必须在查看算法结果前由真值分位数或领域阈值固定。除汇总指标外，报告各算法的适用条件和失败案例，不预设自研方法最优。

## 12. 测试与质量门槛映射

| 验收要求 | 最小测试 |
|---|---|
| 读写一致 | CSV/NetCDF 往返数值、维度、属性对比 |
| 时间轴正确 | 瞬时、平均、累计三类单独测试 |
| 空间网格正确 | 坐标、边界、CRS 与目标形状测试 |
| 守恒 | 已知面积小网格重聚合误差测试 |
| 缺失不静默填充 | NaN/QC 掩膜前后计数测试 |
| 单位安全 | 可转换单位成功、维度不兼容单位失败 |
| 分类安全 | 对连续插值调用明确失败 |
| 观测峰值参与 | 修改可信观测后目标项及结果按预期变化 |
| 不可行处理 | 构造冲突约束，检查状态与显式降级 |
| 模型结构 | profile 必需变量、维度、单位、编码检查 |

每个阶段只运行受影响模块测试和一个端到端样例；发布里程碑再运行全套测试与性能基准。

## 14. 开源依赖记录方案

P1 起在 `pyproject.toml` 固定直接依赖的兼容版本范围，并生成锁文件；在 `docs/dependencies.md` 记录项目名、实际版本、用途、许可证、官方主页和需要引用的论文/DOI。首批预计评估 Pandas、Xarray、NumPy、SciPy、h5netcdf/netCDF4、Pint；GeoPandas、xESMF、xarray-regrid、PyKrige、CVXPY、OSQP 只在对应阶段引入，避免提前增加安装负担。

具体版本和许可证须在实际安装时从官方发布元数据核验，本设计不预填可能过期的信息。

## 15. 待确认问题清单

### 15.1 真实数据

1. 首批真实数据文件、来源许可、样例规模和更新频率是什么？
2. 各污染物的原始单位、时间戳时区、平均窗口和 QC 编码是什么？
3. 站点坐标是否会变化，是否包含站高、仪器类型和检测限？
4. 气象数据的网格投影、垂直坐标、时间语义和风分量定义是什么？
5. 排放是总量、速率还是通量；时间/面积基准和物种映射是什么？
6. 地理数据的 CRS、垂直基准和土地利用编码体系是什么？
7. 哪些数据可用于约束，哪些站点或时间段必须独立留作验证？

### 15.2 物理与算法配置

1. 各变量允许的物理范围和是否允许非负约束？
2. 区间平均/累计数据是否提供 `time_bounds`？
3. 目标网格是否提供单元边界，守恒比较采用面积还是体积权重？
4. 允许外推的业务场景是否存在；若存在，其边界与标记规则是什么？
5. 观测及背景场不确定性如何获得，相关性假设是否成立？
6. 峰值的领域阈值、可信观测条件和峰值邻域尺度如何预先定义？
7. 优化中严格守恒与软守恒的选择标准及容差是多少？

### 15.3 首个模型适配

1. 首个目标究竟是通用 CF-NetCDF，还是具体 CMAQ 版本与具体文件类型？
2. 若为 CMAQ，需要确认版本、网格描述、投影、垂直层、时间标记、变量清单、单位及 I/O API 元数据要求。
3. `GRID_CRO_2D`、`MET_CRO_2D` 或其他文件由本引擎生成、校验，还是仅消费？
4. “兼容”的最终证据是结构检查、官方工具读取成功，还是一次真实 CMAQ 运行成功？
5. 是否有可公开或获准使用的小型官方样例作为验收基准？

## 16. 阶段退出结论

P0 已将核心设计收敛为一个统一数据包、四类协议、显式 Pipeline 和独立验证报告。P1 应先实现 CSV 站点观测到 NetCDF 的时间对齐与往返验证，以最低依赖验证数据语义和模块衔接。空间融合、自研优化、CMAQ 适配和界面均留在后续阶段；在真实字段及模型要求确认前，不对其兼容性或算法效果作结论。
