# 逐源、时段与协调约束下的组合决策

日期：2026-10-24。实现位于平台公共模块，页面处理函数、文件入口和实验客户端共用 `submit_search(mode="Profile")`。本轮没有采用GOLEM优化器；历史入口保留兼容，不代表新机制继续使用它。

## 1. 总体机制

**读取数据与模型场景 → 建立逐源算法候选和连接域 → 三画像联合评分筛选 → 对方案进行单轴或多轴变异 → 真实执行、更新状态与检查协调性 → 保留更优方案。**

模型硬约束不参与软分权衡。独立参考仅在推荐冻结后评价选中产品，不传给处理节点或评分器。小空间可额外穷举审计；其结果与变异阶段分开，不能把穷举收益记成变异收益。

三画像沿用已注册状态属性、模型场景和公共参数乘数。评分仍是 `Σ w_j θ_j [r_j(初始)-r_j(最终)]`，`r(q)=clip((q-acceptable)/(bad-acceptable),0,1)`。多字段按显式重要性聚合。初始基准取各可见源风险指标的平均，比较不同主源时不更换基准。实际执行更新最终状态；未知指标保留区间，同分才优先较少科学步骤。

初筛只使用已审查的保证与可见数据。例如明确的终端非负投影可提供符号保证；没有依据的平滑、峰值、精度等不填虚构收益。画像分与RMSE不是同一指标，本轮不据画像分上升宣称科学效果改善。

## 2. 一份方案具体包含什么

方案是“字段 × 时段 × 逐源处理链 × 融合角色/权重 × 融合后处理链”的有向依赖结构，不是一个固定完整流程的名字。

| 用户提出的问题 | 已实现的决策与验证 |
|---|---|
| 谁主谁辅 | 每个时段可选不同主源及主源占比；其余源分配剩余权重。系数是待比较的方案参数，不是已经知道的可靠性。提供真实标准差、单位及独立性依据时，才允许逆方差方案。 |
| 谁先谁后 | 阶段依赖由 `after` 指定；依赖不冲突的顺序全部展开；替换算法、增加/删除可选步骤和换顺序都对应实际数值执行。 |
| 早融合还是晚融合 | `join_grid=target` 要求各源先达目标网格；`native_common` 可先在共同原网格融合，再由后处理达目标网格。网格不同的源不能直接早融合。 |
| 哪个时段用哪个算法 | 显式目标时间与窗口形成独立决策槽，允许各时段选不同源、算法和参数；上下文长度不得小于阶段要求；不允许目标时间缺口。 |
| 各源是否只能用同一算法 | 各源处理链独立选择，允许相同或不同算法。观测、协变量、训练状态有专用资源端口，不当成同量纲场直接平均。已有站点仿射校正等真实插件可以逐源调用。 |
| 不同结果是否协调 | 融合前检查单位、物理变量、空间/时间语义、CRS和坐标；时间戳相同但区间边界不同也拒绝融合。另记录源间差异、可识别的峰值时间差和时段接缝。超过有证据的阈值则拒绝，不修改输出凑合通过。 |
| 不同变量是否协调 | 多字段在同一基因型中联合选择，合并时坐标必须严格相同；使用已发布的显式跨变量求和约束验证整个产品。测试中8种角色分配只有2种满足关系，其余6种拒绝。 |

重叠窗口采用明确的等权合并，区间字段必须具有一致的重叠区间边界；不是未经验证的动态过渡模型。峰值时间差只是域均值峰值时刻差，平坦或多峰无法唯一识别时保持未知。接缝变化也可能是真实物理变化，阈值须来自任务定义。

**这些检查不等于所有环境动力协调性已被证明。** 当前不能自动推导任意守恒方程、风场动力平衡或模型敏感性。未实现的硬规则会阻止请求；未给阈值的代理指标仅作诊断，不假装已经验收。此版是显式契约下的历史资料准备机制，不宣称实时因果预测能力。

## 3. 自动生成与人工声明的边界

加入 `"composition": {}` 即可启用自动候选构建，不必手写每个源的完整流程：复用算法画像中的已审查转移类型和算法自身兼容性筛选空间方法；按明确的符号需求开放投影；有合法训练观测及许可时开放逐源校正；目标频率必须显式给出，时间语义不能猜测。默认主源与探索系数候选只是有限搜索域，不是科学最优权重。

数据的单位、物理变量、空间/时间语义、稳定源身份和目标域必须可确认。模型偏好及协调阈值需要证据。不能从模型名称猜出这些信息。

需要复现或控制预算时，可冻结 `source_stages`、`post_stages`、`fusion_options`。阶段是算法候选和前置关系，不是指定赢家。阶段可定义可选跳过项；跳过造成的重复链去重。当前每条链最多6个阶段、每阶段最多8个选项；超过10000条分支备选会明确拒绝，而非静默截断。没有沿用旧128张整图上限。

## 4. 变异如何工作

用有限离散基因编码每个“源/字段/时段”的处理链、融合角色和后处理选择。先在有界初筛池中按三画像保守分筛出种子，再从保留方案产生变异。

多数变异只改一轴；也允许同时改多个轴，避免只能改变一个变量而始终被跨变量约束挡住。记录每次父子编号、全部编辑轴、旧/新选择、是否缓存及实际执行成败。新组合可以超出初始筛选名单。精英保留使已观察最优评分不下降，提议次数、执行次数和墙钟均受限。

有限预算不保证全局最优。只有整个已声明空间全部执行，且最优下界不低于其他可用方案的上界，才给出限定域画像分证书；从不声称真实环境效果全局最优。`initial_best_score`、`mutation_best_score`、`final_best_score` 分别对应初始真实执行、变异后、可选完整审计后。

## 5. 到底有多少组合

不能把注册条目数或程序上限当组合数。对冻结请求，精确结构数是：

`N = ∏字段 ∏时段 [ (∏源 C源) × F融合角色参数 × P后处理 ]`。

当前平台注册89项，其中67项状态为available；含适配器/模式，不是67种独立科学方法。相较此前88项，本轮增加一个有真实执行端口的 `fusion.primary_weighted_mean`，数值计算复用既有加权融合内核；用于计算系数的内部尺度不冒充观测不确定度。`prepare.single_background` 是结构边界，不算新增科学算法。

本轮真实数据由同一历史站点证据得到的IDW与普通克里金产品构成，不是独立传感器，不用独立误差假设给它们加权。4种重建方法为nearest、bilinear、cubic、PCHIP，允许省略投影或在重建前/后投影；两种主源角色，主源份额0.75，固定一次时段：

这些数据承袭旧档案的WGS84工作假设，未新增坐标原始证据。此真实配置只按明确的网格/非负需求评分，不能据此判断复杂科学属性的排序能力。

| 计数口径 | 数量 | 证据 |
|---|---:|---|
| 冻结配置的结构组合 | **288** | 每源12条链 × 每源12条链 × 2种主源角色 |
| 全部真实执行并通过 | **240** | 完整执行288张，48张违反最终非负约束而拒绝 |
| 通过产品中精确数值不同的结果 | **32** | 独立回读；不是32种独立科学方法，亦不作近似等价判断 |
| 自动扩展配置的结构组合 | **21,952** | 14 × 14 × 8 × 14，含可选跳过、两种份额及早/晚汇合 |
| 自动扩展域的实际有界搜索 | **20次执行，18通过、2失败** | 从真实输入经公共CLI自动生成；全域可用数未穷举，不填造总数 |

不同数据、变量数、窗口数、参数域会改变这些数。21,952不是整个算法库的永久总组合数；240也不能外推到另一份数据。两时段、多字段增加的是相应决策因子的乘积，不能把不同任务的计数简单相加当总能力。

## 6. 验收事实与负结果

最新目录：`output/composition_20261024/acceptance_v5`。独立审计另见 `output/composition_20261024/independent_audit.json`。

最终157项相关回归通过。7次平台调用，独立回读538份通过的实际数值产品；88条改变基因型的提议均逐项核对编辑轴。核对输入/产品SHA、组合因子乘积、直接符号/缺失指标、评分区间、推荐顺序，以及变异与完整审计的分离。另有12个定向测试覆盖自动候选、早晚汇合、顺序/上下文、时间插值、区间支持、观测训练隔离、跨变量关系和页面/文件入口。

改变数据与模型任务偏好会改变实际推荐。时段功能案例中，变异的内部评分提升0.222222；真实数据固定域的变异提升为0，均保留。它们是机制验收，不是论文效果实验。没有重新宣称此前正式实验已胜最强固定方案；没有运行WRF/CMAQ原生模拟。

中间失败保留：首轮同分方案未优先短链；真实历史产品缺少连续类型元数据；较广回归暴露站点校正与特征森林对不兼容坐标/语义未返回正常拒绝。这些已作定向修复；没有改其数值内核，也没有改GOLEM搜索逻辑。三次插值最低样本要求也补进原算法契约，3点轴会在筛选时排除cubic。

正式效果优越性仍须独立实验，本轮只承诺所列可执行关系与质量门。新图语法不静默复用旧响应记忆库；请求旧bank会明确拒绝，而非冒充已经完成新组合的学习校准。

## 7. 直接使用

已给出两份无需拼接的本地请求：`examples/composition_real_288.json`（完整冻结审计），`examples/composition_auto.json`（自动扩展、有界筛选后变异）。输入文件和显式工程画像已准备，未更换全平台默认科学权重。

在项目根目录PowerShell中：

```powershell
$env:PYTHONPATH='D:/codex/EcoDataEngine/src'
& .venv/Scripts/python.exe -m ecodata.algorithms.platform_search examples/composition_auto.json output/composition_new_request
```

输出目录必须未使用。页面选择Profile、多源任务，在补充需求JSON中加入 `composition:{}` 或完整配置，即调用同一服务；完整目标时间、单位及源身份仍需正确声明。

主要源码：`src/ecodata/algorithms/composition_decision.py`；接入位置：`platform_search.py`、`interface/search_page.py`；定向测试：`tests/test_composition_decision.py`。最终源码与依赖文件指纹见 `output/composition_20261024/source_release_manifest.json`。完整回归记录见同目录 `regression_verified.xml`，较早失败记录不删除。
