# 真实空间环境数据测试模板

模板文件：`examples/templates/spatial_environment_data_template.csv`。

模板只有字段名，不含伪造坐标。使用者必须填写来自真实数据源的经纬度和CRS，并保留来源说明。最低字段要求：

| 字段 | 含义 | 示例规则 |
|---|---|---|
| station_id | 稳定的站点或样点标识 | 不得用行号临时替代 |
| time | 观测时间 | ISO 8601；时区不明确时先确认 |
| longitude | 经度或投影x坐标 | 必须与CRS一致 |
| latitude | 纬度或投影y坐标 | 必须与CRS一致 |
| crs | 坐标参考系 | 同一文件只能有一个有效值，如 `EPSG:4326` |
| variable | 物理变量名称 | 建议使用稳定标准名 |
| value | 数值 | 不在导入阶段擅自填补缺失值 |
| unit | 单位 | 必须对应value，不能只改标签 |
| qc_flag | 质量标记 | 建议使用 `VALID` 或来源系统原标记 |

## 验证链路

1. CSV → GeoJSON：选择“表格 → 点矢量”，确认longitude、latitude和CRS。
2. GeoJSON → NetCDF：选择“矢量 → 栅格”，明确数值字段、真实范围、行列数、重叠规则和像元命中规则。
3. NetCDF → GeoTIFF：选择二维变量或时间切片，检查CRS、nodata、单位和仿射变换。
4. 重新读取三个输出，逐项核对记录/像元数、值域、CRS、单位、质量标记和处理历史。

点转栅格会改变数据结构，必须由用户明确目标网格。没有经纬度、CRS或合理目标范围时停止，不生成坐标，也不把站点名称当作空间位置。

自动测试 `tests/test_p4_model_matching.py::test_spatial_csv_geojson_netcdf_geotiff_chain_preserves_crs_and_values` 已验证这条软件链路；该测试使用明确标注的合成坐标，只证明软件逻辑，不替代真实空间数据验收。
