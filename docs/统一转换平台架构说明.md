# EcoData Engine 1.0 统一转换平台架构

## 用户流程

首页只有“数据转换任务”：上传 → 识别 → 目标要求 → 自动计划 → 执行 → 下载。原算法页面、模型展示页和独立格式页不再作为入口；已有时间、空间、融合和 QP 算法仍保留在核心层，可被统一任务调度。

## 分层

1. `recognition.py`：通过真实解析结果识别格式、结构、变量、单位、时间、空间坐标、CRS、维度和数据语义；不可靠项目进入“待确认”。
2. `io/structures.py`：用 xarray、GeoPandas、Rasterio（GDAL/PROJ）和 PyShp 完成表格、数组、栅格、矢量之间的结构转换、拓扑检查及独立回读。
3. `task.py`：统一任务编排器，只组合既有能力，不重复实现插值、融合或格式编码。
4. `temporal`、`spatial`、`fusion`、`optimization`：保留原有时间转换、空间转换、融合与约束优化算法。
5. `models/requirements.py`：CMAQ、WRF、SWAT+、WASP、MODFLOW 6 的核心需求和用户自定义需求。通过首页 JSON 编辑器保存覆盖项或新增模型。
6. `interface/task_page.py`：唯一普通用户入口，显示识别结果、处理计划、结果和报告。

## 模型输出边界

模型匹配检查必需输入、精确同名变量、单位、目标格式、时间和空间要求。缺少物理变量时阻止执行，不生成虚假变量。当前五个内置模型为 `requirements_only`：平台可输出标准化预处理数据和匹配报告，但未通过真实模型样例验证前，不称为可直接启动模型的原生运行文件。自定义需求可以直接生成平台已验证格式。

## 转换历史

每一步写入处理方法、参数、输入输出摘要、警告和运行时间。CSV/TSV/JSON 等不能完整容纳元数据的格式必须连同 JSON 报告保存。没有参考真值时不显示精度指标。
