# 可靠选优改进方案

2026-10-30。状态：研究与实施设计，尚未改代码、训练或运行新实验。

## 目标与边界

保留现有平台、三画像联合匹配、开放算法构图、随机变异、真实数值执行和硬质量门。改进目标是降低选图误判、限制无实际收益的复杂组合，并在未使用的数据上验证实际选优收益。机制测试通过不能代替效果通过，不能事先保证优于所有固定方法，也不保证全局最优。

不预设人工正确路线，不另建替代三画像的黑箱学习排名器。2022/2023已经检查过的测试结果仅作历史诊断，不用于调新规则后宣称新的独立测试优势。

## 1. 当前实现中需要改变的具体部分

- current_input.temporal_masks只产生一个搜索块；搜索与确认同时从同一稀疏输入移除，5个可见日期最后只剩2个。
- field_mutation目前只有一个掩蔽上下文和单个标量objective；需要承载同图多个固定折的实际响应，不能仅增加搜索种子。
- DAGResponse的实测分支只支持不少于30时刻的逐日单点；本次栅格收益一直UNKNOWN。
- portrait_rules.data_facts对三维时空栅格不计算现有二维variation；属性注册表的测量器/激活器也不能直接表达缺口天数、锚点支持等。因此确实需要补少数有定义的画像测量器，不能只改权重。
- field_mutation.rank仅在误差几乎相同时偏向少节点，无法阻止把微小验证改善换成显著复杂度。
- 已有缓存短前缀终点评价、科学状态去重、删除一元节点、Executor、measured和公共接口继续复用。

## 2. 验证：先描述真实缺口，再生成有支持的比较

### 2.1 描述任务，不读取缺失真值

从输入、目标及已有元数据自动测量：缺失日期数和持续天数、左右有效锚点距离、可见日期数量、日期/月份覆盖、原始像元QA覆盖、细粗空间分辨率比、粗源在对应时段的可见变化和可比较时空支持。稀疏数据不能可靠识别物候阶段时保留未知，不能把月份直接当成物候真值。

必须区分“缺5个日期”和“缺120天”，也区分稀疏分散观测与连续缺口。验证支持报告记录实际留下的有效帧数、被遮日期数、实际括号跨度和季节覆盖，不以support_limited=false表示所有维度都匹配。

### 2.2 稀疏当前输入：留一整日期多折，保留尽可能多的真实输入

对于只有5个可见日期的当前任务，优先使用内部日期的留一整日期折。例如3个内部日期分别留一，每折保留另外4帧；边界外推若不是实际目标，不把端点外推混进普通插值评分。

每折独立创建输入及拟合状态；可见源的同源副本、由该源生成的派生分支同步遮挡并重算，独立粗源保留。所有候选共用固定折，记录逐折误差向量，不能只取最好一折。任意必需折执行失败或输出不满足硬契约，候选不可用，不能删除失败折后计算平均分。

这只能叫内部交叉验证，不能声称验证了“连续缺5日期”或产生了独立确认。不同折之间共享观测是普通交叉验证，不应伪装成独立重复样本。也不能让原先称为确认的日期进入其他搜索折，再继续称其完全未被使用。

### 2.3 长缺口可靠性：需要真实开发病例库补足信息

在较完整的开发时段/区域中构造与目标相近的模拟任务：例如保留5个锚点、隐藏5个真实日期，同时匹配缺口持续天数、季节、锚点位置、QA和分辨率关系。实际上传输入如何稀疏，病例就尽量模拟同样信息支持；不能仅匹配遮挡数量。

每个病例的输入画像只从保留数据和目标生成；隐藏真值只在评价器中出现。用另一个开发窗口或年份做确认，确认值不得进入搜索输入、画像参数校准或规则挑选。若确认结果被用来挑下一张图或调整参数，它就是选择环节；最终科学检验必须另留未使用的年份/区域。

病例匹配依据缺口特征和观测条件，不能依据“哪个历史例子让候选赢”。没有合适的历史支持时，允许输出数值合格的当前最佳结果，但明确低支持等级与不确定性，不能伪造长期缺口可靠性，也不悄悄切回点遮挡。

## 3. 三画像：共同定义一个可实测的目标

### 3.1 三张表的分工

| 表 | 实际参与决策的内容 | 证据来源 |
| --- | --- | --- |
| 数据画像x | 需要解决什么问题、什么验证病例与当前输入相近、哪些风险被激活 | 可见输入与目标的测量；有版本的测量方法 |
| 算法/组合画像 | 在哪些输入条件下有什么真实响应、需要哪些前提、有哪些副作用与成本 | 官方契约；开发病例的真实整图执行；当前候选的逐折实测 |
| 模型/应用需求m | 硬约束及任务目标的重要性 | 用户声明、模型文档中可核实的输入契约、独立下游实测 |

当前只做NDVI重建且没有下游模拟器证据时，目标以真实重建误差和已声明物理门为主，不能声称平滑或梯度代理就是WRF/SWAT收益。

### 3.2 核心数学规则

对整图g在相同第k个验证病例/折上的实测损失定义为：

\[
L_k(g\mid x,m)=\sum_{j\in J} w_j(x,m)\,\frac{e_{j,k}(g)}{s_j},\qquad
w_j=\frac{\theta_j a_j(x)p_j(m)}{\sum_{h\in J}\theta_h a_h(x)p_h(m)}.
\]

- e是完整组合真实运行后的误差或已声明损伤，例如RMSE、绝对Bias；不能由算法能力标签代替。
- a是预先定义、可测的数据问题激活程度。重建任务的基础精度项始终启用，不因缺失比例小就关闭。
- p是模型/应用明确要求的优先级。没有依据的模型敏感性不填成经验常数。
- s是事先固定的单位归一化尺度，来自训练数据、保留输入或明确工程阈值；不能用测试误差选择。
- theta只校准少数允许学习的匹配参数，必须在分组开发集内完成并版本化；不能为提升成绩悄悄改变用户目标。
- 所有候选的有效指标集合J、权重和尺度相同。硬约束先判断，不允许靠其他指标加分抵消越界、缺输出或资源契约失败。

对于仅声明RMSE优先的当前任务，第一版可以只有RMSE这一明确精度项，范围和完整性作为硬门。不能为让“三张表看起来复杂”而强加未知的多指标权重。三画像仍通过任务验证设计、条件算法响应、合法性和目标定义共同参与决策。

执行前，算法画像仅依据有适用条件的开发响应提供收益区间，辅助候选优先级；新组合没有证据就保留UNKNOWN并允许随机探索。执行后，用相同折的整图实测响应更新同一个评分体系。真实收益来自实测，不能把预测增益与同一份实测精度再重复相加。

新增栅格响应适配应复用多折评价的结果，避免另跑一套不相干的探测。单算法响应可以帮助提议，完整组合的数值收益、前后顺序与交互必须整图执行确认；不把多个单算法分数相加冒充组合得分。

### 3.3 共同强参照与组合收益

在开发期冻结一个合法的简单强参照B，所有候选都在同样折、相同支撑范围下比较：

\[
\Delta_k(g)=L_k(B)-L_k(g).
\]

正值才表示优于共同参照，不再与各候选自己较弱的分支比较。B只作比较，不强迫平台选择它。新任务契约不支持B时按预先声明的适配规则处理并记录，不能用测试误差临时换参照。

对少量最终候选做合法删节点/替换对照，实际执行后才记录某节点的条件贡献。删除导致输入端口或语义不合法时不能据此判该节点有数值收益。共同增益是排序解释和复杂升级依据，不是重复计入精度的“协同奖励”。

### 3.4 学习能力怎样落地

保留“条件画像—响应—匹配参数”的可解释校准：病例记录可见特征、目标/模型契约、完整图及顺序/分支、逐折数值响应、失败、成本和证据版本。初期采用有支持的条件分组统计/相似病例；样本少或跨场景外推时增大不确定性并报告未知，不训练一个替代三表的黑箱排名器。

复用现有有界规则校准框架，但新增开放DAG、折、目标、参考支撑与证据角色的记录适配。原scoring_calibration读取的是完整Profile候选表，不能直接把它当成已支持开放DAG；也不能只用搜索赢家训练或把未执行图填成差结果。权重/容差/停止阈值只在开发分组内校准，留组检验后冻结。

## 4. 复杂度：没有可靠额外收益就选择简单图

### 进入复杂度比较前，先统一证据等级

若当前多折足以覆盖目标缺口，优先以这些折的整图实测损失比较。若当前只有单日期留一支持而目标是长缺口，有匹配历史病例时，以同支持长缺口病例的整图响应作为长缺口比较依据，当前局部多折另作一致性/明显退化检查；不能把较容易的局部误差与长缺口误差随意平均成一个看似可靠的分数。没有匹配历史支持时，只能给出低支持的暂定推荐，不能声明可靠收益。

所有候选必须使用同一批依据输入画像预先选定的病例及同一证据规则，不能让各候选自行挑有利病例；匹配病例属于开发选择数据，独立确认和最终测试仍另行隔离。这个分层规则避免通过任意指定“历史分与当前分的混合系数”掩盖证据不匹配。

不规定最多两三个节点，也不因为某个操作重复就认定无效。先识别同一科学状态、缓存复用和不改变输出的操作，复用已有码去重与短前缀评价。

改进最终选择规则：先找跨折平均实测损失最低的合格图g*，再构建误差近似等价集合：

\[
\mathcal G_\delta=\{g:\bar L(g)\leq\bar L(g^*)+\delta\}.
\]

在该集合中按有效科学节点数、更低成本、稳定ID选择。delta是开发期预先确定的实际等价容差，不能沿用浮点舍入量，也不能在测试结果出来后挑。复杂图要有跨多个受支持时间块/病例的、超过容差的改善，才值得作为更优推荐；同时报告最差组退化。

例子仅解释规则：两节点误差0.100，十节点0.0998，若冻结容差为0.002，应选择两节点；若十节点在不同病例上稳定达到0.085，应保留其真实收益。此数字不是本项目已测结果或拟定阈值。

可借鉴one-standard-error的简约选择思想，但当前时空折重叠、病例很少，不能直接用像元数开根号制造极小标准误，也不声称该容差是普适置信保证。统计独立单位应是地区、年份或合适的独立事件组，校准失败时保留不确定性。

最后对少量候选做合法剪枝：删去某节点后如果保持同样任务契约且实测不劣，就保留短图；所有额外验证计入成本。简洁选择用于最终排名和精英保留；随机探索仍保留非精英及未知候选，避免把可能需要多步协作的组合在中途全部剪掉。

## 5. 怎样证明这次确实改善选优

### 第一关：固定候选，先检验“尺子”

先冻结一个仅用于诊断的候选图库：由已有开发搜索轨迹及合法随机生成构造，覆盖多种长度、逐源/顺序和已有固定方法，不能看测试效果挑图。该有限图库不是平台生产搜索的固定候选池。

同一批图、同一批新任务，分别用当前单块评分与拟议多折三画像/简约规则选图。决策封存后，真实执行并评估外部隐藏值，计算：

- 选图遗憾R = 选中图实际损失 − 图库中实际最低损失；图库最低只作事后评估，不能传给选择器，也不能称全局最优。
- 评分排序与实际效果排序的关系、相对共同强参照的逐任务胜负、最差组误差和失败率。
- 节点数、所有真实探测/折/失败/剪枝/部署成本，以及低支持任务是否被正确识别。

如果固定同一批图仍不能更少选错，就不能把偶然搜到另一张图当作评分创新成功，应停在开发阶段查原因。

### 第二关：再比较完整随机变异搜索

第一关有开发证据后冻结方案，在未使用地区/年份上比较：现有选择策略、多折但无画像收益、完整画像收益但无简约控制、完整新机制，以及开发期冻结强固定方案。可按消融需要增加随机提议对照；各组使用同一算法库、数据、硬门及种子。

比较预算以全部真实算子调用/累计成本计，包含多折、画像探测、失败、简化与部署，不只比较图数量。每个最终候选和短前缀都必须完成同一套必需折；缓存键包含折输入及拟合状态指纹，严禁跨掩码泄漏。

主要效果指标是独立任务的选图遗憾与实际损失；同时报告逐任务胜率、最差退化、稳定性和成本。折与种子重复不能冒充新地区。正式样本量及允许退化/实际改进阈值由开发试验的精度需求提前制定；小样本只作探索，不给虚假显著性保证。

验收要同时区分：机制正确、在可支持任务上减少选图错误、独立真实效果有实际价值。仅平均改善而大部分任务变差，或仅机制通过，不验收为“稳定可靠选优”。如果新任务不适用或效果不提升，保留负结果，不能反复利用同一测试集改规则直到出现优势。

## 6. 最小改动与成本控制

| 现有公共模块 | 复用内容 | 必要增补 |
| --- | --- | --- |
| current_input.py | 输入、别名隔离、目标/质量检查 | 任务缺口描述、多折生成、独立确认与支持报告 |
| field_mutation.py | 随机提议、Executor、短前缀、去重、账本 | 同图逐折响应、共同聚合规则及近等价简约保留 |
| dag_response.py / composition_scoring.py | 可见实测响应、共同参照计算思想 | 栅格整图响应适配，与主评价共享数值结果 |
| portrait_rules.py / attribute_registry.py | 三画像契约、版本、硬软区分 | 少数明确可测的时空任务属性与响应提供器 |
| scoring_calibration.py | 有界参数校准、分组/范围指纹保护 | 开放DAG/完整诊断病例的证据适配，不放宽防泄漏要求 |
| 页面/工具公共入口 | 相同请求与输出、版本失效 | 展示折支持和评分依据；不写实验专用选择逻辑 |

首版用固定小组折并共用缓存和响应，不急着引入新的黑箱、贝叶斯优化或分级淘汰系统。只对最终少量候选做删节点检查，所有候选最终比较的必需折一致。新多折分布下的早停参数也须用开发轨迹重新检验，不能把旧单点/单块容差直接视作统计保证。

## 7. 已核实、适合借鉴的方法

1. Roberts等：时空分块验证需服务于实际预测目标；过度删去可用支撑也会人为制造外推。借鉴其任务导向与避免不必要外推原则，不照搬某个固定分块大小。[原文](https://doi.org/10.1111/ecog.02881)
2. CAST的CreateSpacetimeFolds：按预定义时间、空间或时空组构造折，适合借鉴接口和分组思想，无需引入整个R框架。[官方文档及源码入口](https://hannameyer.github.io/CAST/reference/CreateSpacetimeFolds.html)
3. one-standard-error思想：性能相近时保留较简单方案。借鉴选择原则，不能把存在相关性的小样本折当成独立数据来套标准误。[mlr3官方实现](https://mlr3fselect.mlr-org.com/reference/mlr3fselect.one_se_rule.html)、[scikit-learn复杂度平衡示例](https://scikit-learn.org/stable/auto_examples/model_selection/plot_grid_search_refit_callable.html)
4. Cawley与Talbot：优化有限验证集上的选择准则本身也可能过拟合，因此需要保留独立效果评估，不把更多搜索当成泛化保证。[JMLR原文](https://www.jmlr.org/papers/v11/cawley10a.html)

这里借鉴的是与当前故障对应的验证、响应和简约决策方法；没有提出更换随机变异算法，也没有把其他AutoML框架整套接入。
